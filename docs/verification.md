# 排查与验证记录

本记录描述一次 Android 环境下的排查结果。个人设备型号、构建号及原始截图不公开。

## 对照结果

| 条件 | 观察结果 | 能得出的结论 |
| --- | --- | --- |
| 原有 Magisk 排除配置 | Root 弹窗 | 勾选排除列表不保证覆盖所有检测 |
| 仅禁用 11.3.1 的 IsoService | 仍弹窗 | 单独禁用服务不足 |
| 11.1.0 单独禁用 XMPushService | 仍弹窗 | 不能据此把推送服务列为必要处理项 |
| 11.1.0 单独重置 envc.push | 重写 `root=1b6a281f9` 并弹窗 | 该轮不是单纯旧记录残留 |
| 内置 Zygisk 关闭并处理风险记录，11.1.0 | 没有 Root 弹窗，但出现升级拦截 | 不能将 11.1.0 视为最终可用方案 |
| 内置 Zygisk 关闭，11.3.1 的 IsoService 保持启用 | `root=1b6a281f8`，仍弹窗 | 还有独立检测结果回调路径 |
| 内置 Zygisk 关闭 + IsoService 禁用 + 风险记录重置 | 11.3.1 两次冷启动进入首页 | 可解决启动问题，但不能满足其他应用依赖 Zygisk 的需求 |
| 重新开启内置 Zygisk，保留强制排除及 IsoService 禁用 | `root=1b6a281f2`，再次弹窗 | 内置 Zygisk 的该组配置仍不足 |
| Zygisk Next + 强制排除 + 匿名内存 + IsoService 禁用 + 风险记录重置 | 11.3.1 两次冷启动进入首页，第二次等待至少 35 秒 | 本次最终有效组合 |

最后一组同时确认 Next 的 `inject_state=1`、`enforce_denylist=1`、`memory_type=1`、`linker=1`，并确认既有 Zygisk 模块已加载。

## 检测链与证据边界

静态分析定位到主界面的 `checkIsRoot` 调用 `RootUtil.isDeviceRooted`，其中通过 `H.gha("root")` 取得 native 检测结果，还有 Java 层的常见 Root 检查。

运行时读取检测库并分析其记录格式，识别出 Base64 + SM4-ECB 的 `envc.push`。这里只分析检测状态，不包含账户令牌或交易数据。

- 11.1.0 的 `b6a281f9` 分支涉及 Zygisk/Shamiko 相关内存特征检查。不能据此断言一定是 Shamiko 本身触发。
- 11.3.1 的 `b6a281f8` 对应独立服务检测结果传回主进程、经 `H.he` 处理的路径。独立进程内部究竟命中了哪个系统特征，没有进一步细分。
- 重新开启内置 Zygisk 时观察到 `b6a281f2`，这里仅记录实验相关性，不给这个原因码编造通用含义。
- 原因码和内部实现属于特定构建的分析结果，不是银行公开的错误码规范。

## 保留了什么

- 使用官方 11.3.1 原包，没有修改 APK、签名、包名。
- 保留 Magisk 和 Root，以实际 `su` 返回 uid=0 核对。
- 保留原农行数据目录，目录 inode 在过程前后相同。这个指标只支持“没有替换整个目录”，不是逐文件完整性或登录有效性证明。
- 没有执行清除数据、卸载原应用或账号退出。
- 检测记录修改前进行了备份，最终文件由应用自行删除，没有设置不可变属性。

## 未验证事项

没有登录、账户查询、支付或转账测试。没有验证 VPN 场景，没有逐个测试其他应用里的 Zygisk 模块。没有跨机型、跨系统或跨 APK 构建测试，也没有验证每项设置各自独立的必要性。

公开仓库仅提供教程、匿名操作示意图和限定范围的辅助脚本，不上传银行 APK、模块 ZIP、解密后的库、设备内存转储、完整日志或个人应用数据。

## 排除列表界面修复

后台排除条目存在，但管理器只显示 WebView Zygote。系统日志表明 Magisk 的 GET_INSTALLED_APPS 操作不被允许。在 root shell 中仅为 Magisk 设置该操作为 allow，再重新打开管理器后，农行及其他应用恢复显示。没有修改任何应用的排除勾选状态，也没有清除应用数据。
